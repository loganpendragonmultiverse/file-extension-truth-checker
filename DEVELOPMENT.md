# Development handoff

The public contract is conservative, read-only identification. Never rename files, execute inspected content, or claim that an extension match proves safety. Every signature must have a focused fixture. Every feature release must update tests, version metadata, `CHANGELOG.md`, README descriptions and limitations, GitHub release copy, repository metadata, and the Forge catalog together.

Initial verification covers PNG/JPEG aliases, DOCX and EPUB ZIP-family distinctions, collision reporting, and unknown-signature restraint.

The 1.1.1 audit makes report writes exclusive, bounds EPUB identifying reads,
reports failed discovery rather than silently succeeding, and treats dangling
links as collisions. Preserve the conservative signature interpretation and
read-only contract. Native CI coverage remains required before release.
